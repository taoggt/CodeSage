## 答疑：Settings 配置加载机制（用户读 core/config.py 时提问）

- 讲透三问：配置怎么被加载 / settings_customise_sources 有什么用 / 何时被调用。依据 pydantic-settings 2.15.0 源码（main.py：`__init__` → `_settings_init_sources`（第 442 行调用钩子）→ 返回值 `+ (default_settings,)` → `_settings_build_values` 逐源 deep_update）+ 打桩探针实测（跑后已删）。
- 关键结论：① 钩子**每次实例化恰好调用一次**（打桩后 0 次 → 实例化 N 次 = N 次调用，实测吻合），不是 import 时；② 优先级实测：init > env > .env > codesage.toml > 代码默认；③ 库自动追加 DefaultSettingsSource 兜底，钩子返回值无法移除它；④ codesage.toml 与 .env 都相对 CWD 动态探测（每次实例化重新探测）。
- 教学文档 01 篇已覆盖三层来源与配置项表格，但未讲"钩子调用时机/库内部调用链"，可作为可选深入补充。
- 追加答疑（同日）：`extra="ignore"` 的含义。pydantic-settings 对 BaseSettings 的默认是 `extra='forbid'`（main.py 第 617-618 行），项目显式放宽为 ignore。实测：会送入校验的"未知键"来源有 toml 未知键（含整节）、.env 未知键、构造参数；ignore=静默丢弃 / forbid=ValidationError / allow=进 model_extra。环境变量未知键**不会**被收集（EnvSettingsSource 逐 model_fields 取值，base.py 第 598 行）；嵌套子模型（LLMSettings 等普通 BaseModel）自身默认 ignore，typo 恒静默。Jackson 对照：FAIL_ON_UNKNOWN_PROPERTIES / @JsonIgnoreProperties(ignoreUnknown=true)。
- 追加答疑（同日）：SettingsConfigDict 五参数逐一讲解（env_prefix / env_nested_delimiter / env_file / env_file_encoding / extra）。实测：环境变量与 .env 的键**大小写不敏感**（小写前缀同样生效）；单下划线 `CODESAGE_LLM_BASE_URL` 无效（必须双下划线）；.env 中文值正常读入；`env_file_encoding` 在本版本默认已是 utf8（dotenv.py 第 85 行 `encoding or 'utf8'`），显式写属防御性声明。

## 答疑：pipeline/review 事件回调装配层（连续 4 轮追问）

用户从 `pipeline.py:40` 起逐行精读，连续追问并已讲透（均配真机 demo，`.venv` 直接跑 `_emit`/`co_freevars`）：

- `EventHook = Callable[[str, dict[str, Any]], None]` 类型别名：运行时零校验（别名是普通赋值语句、删掉程序照跑），静态层（mypy/IDE）做结构匹配、无须声明实现；Java 对照 `BiConsumer<String, Map<String, Object>>`。坑：第 14 行 `from __future__ import annotations` 管不到第 40 行（那是真执行的赋值），故依赖 requires-python ≥ 3.10。
- 鸭子类型实证：普通函数/闭包/lambda/`__call__` 实例四种形态均可直接作 `on_event`，零 implements；**前提是形态对**。`_emit` 的 `try/except Exception: pass`（pipeline.py:372-375、loop.py:224-227）会把形态错的回调（如零参数）的 TypeError **静默吞掉** → "事件静默消失"是排查陷阱；常见根因还有 quiet 模式下 `on_event=None`。
- 工厂与括号：`review.py:163` 传入字段的是 `_make_progress_printer()` 的**返回值**（内层 `on_event`，`:86 return`），不是工厂本身；`f` 与 `f()` 之别是 Java→Python 头号坑；忘写括号 → 存工厂本身 → 调用时 TypeError 被吞 → 静默失效（Java 编译期可拦）。
- "为什么要套一层 on_event"（工厂+闭包）：核心 = 回调签名被契约锁死（`(str, dict) -> None`），配置/状态只能从外层作用域注入（闭包"背包"）。同款正牌证据：`_make_compressor`（pipeline.py:330）的 compressor 捕获 `('budget', 'client', 'router')`（`co_freevars` 实测），`_make_progress_printer` 的为空 `()`（留白扩展位）。诚实地评价：当前这层可等价删掉，但保留理由 = 项目一致性 + 加配置/状态（verbose、去重、计数）不改调用点。
- 可并入《教学文档》：pipeline 管线篇可补"事件钩子 + 工厂闭包"小节；上述 demo（co_freevars、"忘括号静默失效"）是现成素材。
