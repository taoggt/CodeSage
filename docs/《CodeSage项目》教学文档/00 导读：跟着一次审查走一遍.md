# 导读：跟着一次审查走一遍

这组文档把 CodeSage 从上到下拆开讲一遍——但换一种讲法：**不按模块目录讲，而是跟着一次审查的执行顺序讲。**

你在终端敲下 `codesage review ./your_project`，到看见一份带评分的报告，中间发生了几十件事：文件被筛选、代码被解析、13 条规则依次跑过、一份"任务简报"被拼出来、模型开始一轮轮读代码并调用工具、上下文被压缩过、发现被合并去重、报告被渲染并落盘。这组文档就沿着这条线，**从第 1 站走到第 8 站**，每到一个环节停下来把它讲透——涉及的每个函数参数、每个配置项、每处设计取舍都不跳过。

## 这组文档写给谁

写给正在学习这个项目的人——尤其是**从 Java 转过来的 Python 新手**。

Python 和 Java 的差异不只是语法糖：装饰器不是注解、`with` 是加强版 try-with-resources、类型注解不参与运行、默认参数有个众所周知的坑、列表和字典都是"引用类型"且可变……这个项目恰好把大部分差异都用到了，所以每一站里遇到值得展开的语法，都会插入一个 **【Python 加餐 N】** 小节：讲清楚它是什么、在这里为什么这么用、以及和 Java 的对应或区别。文末（第 12 篇）有一张把全部加餐汇总成对照表的总索引。

## 一次审查的完整地图

```text
$ codesage review ./your_project
        │
        │  ① 命令层（第 01 篇）
        │     Typer 解析参数 → 加载配置（env > toml > 默认值）→ 组装 ReviewOptions
        ▼
   run_review()                     ← 管线总控（pipeline.py）
        │
        │  ② 阶段一 · 扫描（第 02 篇）
        │     四道筛子筛文件 → 文件清单 + 跳过原因；--changed 时叠加 git diff 过滤
        ▼
        │  ③ 阶段二 · 确定性分析（第 03 篇）
        │     13 条 AST 规则 + Ruff / Bandit / radon → 候选发现（全程零 Token）
        ▼
        │  ④ 阶段三 · Agent（第 04–07 篇）
        │     组装（提示词 / 工具 / 预算 / 记忆）→ ReAct 循环 ⇄ LLM ⇄ 工具
        │     （循环内自动发生：预算检查 · 记忆压缩 · 工具执行 · 停止判定）
        ▼
        │  ⑤ 阶段四 · 合并（第 08 篇）
        │     驳回过滤 → 跨来源去重 → 评分
        ▼
        │  ⑥ 阶段五 · 输出（第 08 篇）
        │     Rich 终端渲染 / Markdown / JSON 导出 + SQLite 全局落盘
        ▼
   报告 + 退出码（0 正常 / 1 CI 阈值 / 2 参数错误）
```

对照源码里 `pipeline.py` 的注释，前五步就是它写在文件开头的五个阶段——这组文档的主线（第 01–08 篇）与之一一对应。

## 阅读约定

- 内容全部来自 `src/codesage/` 的源码（62 个文件，约 6637 行），不含推测。类名、方法名、字段名、字符串常量都与源码逐字一致。
- 引用的代码块直接摘自源码；截取时会在上下文中说明。注释里的错别字也不改（比如守则 4 里的 "reading"），保证"你看到的 = 代码里有的"。
- **参数说明**统一用表格或逐项列表给出（名称 / 类型 / 默认值 / 含义）；**配置项**给出环境变量名与 `codesage.toml` 写法；**示例**尽量给真实的输入输出。
- 对「定义了但没有被使用」的方法、字段、枚举值，会明确标注，不写成"已实现"——第 12 篇的"诚实清单"会把它们汇总成一张表。
- **【Python 加餐 N】** 是写给 Java 背景读者的语法专题，可以跳过，跳过后不影响主线；文末索引可随时回查。
- 跨篇引用格式：「第 04 篇」指篇目；「6.2」指对应篇内小节号（篇号与小节前缀一致，如 6.2 在第 06 篇）。

## 快速开始（先看到东西，再理解原理）

```bash
# 零成本模式：只跑确定性分析，不需要 API Key
codesage review examples/demo_target --no-llm

# 完整模式：确定性分析 + LLM 深度审查（需在 .env 配置 API Key）
codesage review ./your_project

# 评测：确定性层基线（无需 API Key），量化检出率 / 误报率 / 成本
codesage eval --mock --tag baseline
```

`examples/demo_target/` 是项目自带的演示靶场——6 个文件里刻意植入了各类缺陷，跑第一行命令能看到大约 27 条发现、评分 0 分（靶场就是拿来扣分的）。
