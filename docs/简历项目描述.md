## 版本 A：主推（核心工作分点）

**2026.09 – 2026.10　CodeSage · AI 代码审查 Agent（个人项目）**

**项目简介**：CodeSage 是一个跑在终端里的 AI 代码审查 Agent——执行 `codesage review ./src` 即可扫完整个项目，输出按 P0–P3 分级、带文件行号与修复建议的评分报告，能直接接入 CI 卡住不合规提交。针对"大模型读全量代码又贵、给的建议又容易泛泛而谈"的问题，采用确定性静态分析与 LLM 语义推理分层协作：文件筛选、AST 规则匹配、Ruff/Bandit/radon 扫描等高确定性任务全部下沉到零 Token 的工程代码，模型只负责复核候选与推理逻辑问题。

**技术架构**：Python 3.10 + openai SDK（OpenAI 兼容 / DeepSeek）+ Typer + Rich + 标准库 ast + Ruff + Bandit + radon + SQLite + pytest + uv

**核心工作**：

- **搭通"一条命令出报告"的审查主链路**：输入目录或单个文件后，自动完成扫描过滤、按函数切块、静态分析、Agent 复核、去重聚合与评分，最终输出带代码定位和修复建议的分级报告；同时支持只审 Git 变更（增量）、按安全/性能角色聚焦、`--fail-on` 让 CI 按严重级拦截提交。
- **把"不需要推理的判断"从模型手里拿走**：自研 13 条 AST 规则盯住可变默认参数、裸 except、eval/exec、硬编码密钥这类模式化缺陷，再叠加 Ruff/Bandit/radon 扫出候选问题；模型不读全量代码，只负责复核候选、补充逻辑错误与边界条件、给修复建议。这样噪声在零 Token 阶段先被消掉，模型不必对着几千行代码泛泛而谈，成本和误报同时下降。
- **自己写 Agent 循环，让模型"边查边判"而不是一次性作答**：基于 function calling 实现 ReAct 循环，模型可读文件、搜代码、列符号、调分析器、查最佳实践库、提交或驳回某条发现（共 7 个工具），自主决定先看哪段、什么时候下结论；另设四类退出条件（模型不再调工具、轮次上限、Token 超预算、连续几轮零新发现），避免死循环和空转烧钱，全程不依赖 LangChain 类框架。
- **解决长审查把上下文塞爆的问题**：把对话切成冻结区（系统提示，永不压缩、可持续命中缓存）、压缩区（中间轮次压成结构化摘要，强制保留已提交的发现）、活跃区（最近几轮保留原文）；到 60% / 80% 两个水位分别触发回合边界压缩与强制压缩，95% 熔断并输出已有结果，审查几十个文件也不会中途失败。
- **让"改得对不对"能被验证，而不是凭感觉**：自建 Harness 用真实缺陷案例跑完整链路，按行区间重叠软匹配算检出率、误报率、F1 与单案例成本，支持两版 Prompt 做 A/B 回归；用户标"误报"后沉淀进错题本，下次审查按项目注入 few-shot 经验，形成"反馈—沉淀—注入—回归"闭环。当前 5 条种子案例上确定性层检出率 100%、F1 0.87、零 API 成本。
- **回头优化自己的审查速度**（版面允许再加）：cProfile 逐层剖析发现耗时不在分析本身，而在 Bandit 为每个文件起一次子进程、以及 Windows 下临时目录的写删开销；改为单次批量扫描 + 零临时文件后，62 个文件的全量审查从 92.7s 降到 2.7s。

## 写法原则（后续自己改时沿用）

技术项目最容易写成的样子，是把参数表抄上去——`function calling + 7 个工具 + 四类停止条件`，读的人知道你用了什么，但不知道这东西是干嘛的。三条约束：

1. **每条先答"解决了什么问题"，再答"怎么做的"**。"把不需要推理的判断从模型手里拿走"比"13 条 AST 规则 + 3 个分析器"先出现，读者才有落点。
2. **数字只做证据，不做主语**。数字放句尾当结果（"审查几十个文件也不会中途失败"），别放句首当卖点（"62 文件 2.7s、34 倍提速"）。
3. **每个技术名词后面跟一句人话**。`ReAct` 后面必须跟"模型可读文件、搜代码、调分析器，自己决定看到哪"；`三区记忆` 后面必须跟"审查几十个文件也不会中途失败"。名词是给面试官深挖的钩子，人话是让 HR 和初筛的人能过。

面试官看完这五条，应该能复述出："他做了一个命令行工具，能自动查代码问题，为了省钱把能确定的部分自己写规则算了，剩下的才给大模型，而且他自己搭了套评测证明有效。"

## 与 Ragent 的搭配建议

两条项目要形成互补而非重复：

| | Ragent（Java） | CodeSage（Python） |
|---|---|---|
| 证明什么 | 工程规模、企业级架构、RAG 全链路 | Agent 内核原理、成本与评测思维 |
| 面试主线 | "我搭过一个平台" | "我自己写了一个 loop，并且能证明它有效" |
| 层级 | 平台 / 应用 | 内核 / 工具 |

**最可能被问的三题**（提前准备）：

1. **为什么不用 LangChain？** —— 压缩时机与 Token 预算需要精确控制，框架抽象反而挡路；自研 loop 每步有 trace，出幻觉能定位；一个月周期内学框架→撞边界→绕开，不如直接写。
2. **100% 检出率怎么来的？** —— 5 条种子案例、确定性层、软匹配口径；承认样本小，讲清如何扩充（见 `examples/eval_dataset/README.md`）。
3. **LLM 那层到底有没有用？** —— 确定性层只覆盖模式化问题，逻辑错误、边界条件、修复建议必须靠语义推理；分层的价值是让 LLM 只看候选，而不是读全量代码。
